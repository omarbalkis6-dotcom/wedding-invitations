# Publishing these three sites, and selling them

This folder is **deploy-ready**. Everything is self-contained: each design is a
single `index.html` with its CSS, JavaScript and images already embedded. There
is no build step and nothing to install.

```
wedding-websites-for-sale/
├── index.html            ← showcase page linking the three demos
├── midnight-gold/index.html
├── blush-heart/index.html
└── arabic-arch/index.html
```

---

## Getting a public link (fastest first)

### 1. Netlify Drop — about 60 seconds, no account needed to see it live

1. Open <https://app.netlify.com/drop>
2. Drag the whole **`wedding-websites-for-sale`** folder onto the page
3. You immediately get a URL like `https://calm-marzipan-1a2b3c.netlify.app`

That single URL gives you all four pages:

| Page | URL |
| --- | --- |
| Showcase | `https://your-site.netlify.app/` |
| Midnight Gold | `https://your-site.netlify.app/midnight-gold/` |
| Blush Heart | `https://your-site.netlify.app/blush-heart/` |
| Arabic Arch | `https://your-site.netlify.app/arabic-arch/` |

Sign up (free) to keep the link permanently and to rename it to something
sellable like `wedding-invites.netlify.app`. Free tier is plenty for this.

### 2. Cloudflare Pages — same idea, very fast worldwide

<https://pages.cloudflare.com> → Create project → Upload assets → drag the
folder. Free, and it handles a custom domain well.

### 3. GitHub Pages — best if you want it in a repo

Needs a GitHub account and `git`. Once you have both, from this folder:

```bash
git init && git add -A && git commit -m "Three wedding invitation designs"
```

Then create a repo on GitHub, push, and turn on Pages in
**Settings → Pages → Deploy from branch → main / root**.

### A custom domain

For selling, a real domain reads far better than `*.netlify.app` — something
like `zaffa.studio` or `daawa.co`. Buy at Namecheap or Cloudflare (~$10/year)
and point it at whichever host you chose; all three support custom domains free.

## Before you sell — please read

**The code is yours.** These sites were built for you. Sell them, rename them,
charge whatever you like.

**The fonts are fine.** Google Fonts (Cormorant, Italiana, Jost, Parisienne,
Playfair, Amiri, Aref Ruqaa, Reem Kufi, Tajawal) are open-source and free for
commercial use.

**The photographs need care.** The photos in *Arabic Arch* come from Unsplash.
The Unsplash License allows commercial use without attribution, so **using them
in a demo is fine**. But two cautions:

- Do not sell the photographs *themselves* as part of a template package. The
  Unsplash License does not allow redistributing the photos as a standalone
  product, and template marketplaces (ThemeForest, Creative Market) will reject
  a submission that bundles them.
- For a paying client, replace them with the couple's own photographs. That is
  what they are paying for anyway.

The safest packaging: ship the template with **your own** photos or plain
placeholders, and keep the Unsplash images only on your public demo.

**Designs one and two** use artwork generated by code (`_generate.js` in each
project folder), so they carry no third-party image licence at all.

## Customising for each client

Everything a couple needs changed lives in one place — the `CONFIG` object at
the top of the `<script>` in each file:

```js
var CONFIG = {
  bride: 'Amelia',
  groom: 'Sebastian',
  date: new Date(2026, 10, 14, 9, 0, 0),   // months are 0-based: 10 = November
  endDate: new Date(2026, 10, 14, 22, 0, 0),
  venue: 'Villa Belvedere Gardens, Ravello',
  defaultGuest: 'Beloved Guest'
};
```

Change the date there and both the countdown and the calendar download follow.
Names, family names, venues and times in the visible text are plain HTML — search
for them and replace.

**Per-guest links.** Add `?to=` to any link and the invitation greets that guest
by name:

```
https://your-site.com/arabic-arch/?to=أبو%20خالد
```

This is a strong selling point — one site, a personalised link per guest.

**Collecting real RSVPs.** Right now replies are saved in the guest's own browser
(`localStorage`), which is perfect for a demo but does not reach the couple. To
collect them for real, post the `entry` object in the form's submit handler to a
Google Form, Formspree, or your own endpoint. Ask me and I will wire it up.
